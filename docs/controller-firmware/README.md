## TST 2026-08-24 — протокол

Файлы `LowInit.c`, `Prepare_Beverage.c`, `USART.c` совпадают с `2026_08_12_chibrin`. Изменились `Vita_Flow.c` и `Func.c`.

- **0xBB** (`WriteWaterPumpModel`): `buff_rx[1]` = `koef_w100` (обычная вода), `buff_rx[3]` = `skoef_w100` (газировка). Default воды 180 (1.80). В C default газировки задан как `skoef_w100=300` при типе `unsigned char` (переполнение, максимум 255).
- **0xBC** (`ReadWaterPumpModel`) ответ `0x88`: `[koef_w100, koef_w100, 0x00, skoef_w100, skoef_w100]`.
- **0x52** service: режим `11` — тестовый налив газировки (`SWATERFILLING_TEST`, клапан `WTR_CARB_VALVE`). Режим `10` по-прежнему фильтрованная вода.
- **ChooseDrink `Type_of_water`:** UART-комментарий и клапаны: `0` фильтр, `1` холод, `2` газ. В `Mors_Syrup_Routine1` импульсы газировки считаются при **`Type_of_water==3`** (не `2`). Android шлёт SPARK как `2`. Это расхождение вендора: газ открывает клапан, но `Koef_SWater` по этому коду не применяется.

Android не должен писать 0xBB пятью одинаковыми байтами коэффициента воды — иначе `skoef_w100` затрётся. Кодирование: `WaterPumpModelCodec`.
