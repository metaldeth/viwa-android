# Генерация фото для карточек вкусов (horizontalCard)

> Когда возвращаемся к новым вкусам / перегенерации PNG — читать этот файл **до** генерации.

## Куда кладётся ассет

| Параметр | Значение |
|----------|----------|
| Путь | `app/src/main/assets/viwa_electron/img/horizontalCard/{tasteMediaKey}.png` |
| Размер | **160×156** px |
| Формат | PNG **32-bit ARGB** с прозрачностью |
| Маппинг | `ViwaElectronAssets.MEDIA_KEY_TO_PNG` + `TasteMediaKeyCatalog` |
| UI | `ViwaDrinkCard`: фото **слева** 160×156, `ContentScale.Crop`, карточка 301×156 |

Эталон по композиции: `orange.png`, `lemon.png`, `raspberry.png`.

## Композиция (критично)

Фото сидит **слева** на карточке. Справа — название и цена (не часть PNG).

| Край зоны фото | Можно ли резать фрукт |
|----------------|------------------------|
| **Левый** (внешний край карточки) | **Да** — фрукт может уходить за край |
| **Верх** / **низ** (внешние края) | **Да** — допустим кроп; снизу обычно больше, сверху меньше |
| **Правый** (граница с текстом внутри карточки) | **Нет** — не резать фрукт «внутри» карточки; силуэт к правому краю фото должен заканчиваться мягко, с воздухом/прозрачностью |

Антипаттерн: фрукт прижат вправо с большой пустотой слева (как «правосторонние» стоковые кадры) — на карточке выглядит наоборот от эталона.

## Масштаб

Карточка **низкая** (156 px по высоте). Фрукт должен быть **крупным**: почти на всю высоту зоны фото (ориентир ~85–100% высоты кадра), не мелкий предмет по центру с полями.

## Фон

- Только **прозрачный** фон (альфа), не белый и не чёрный прямоугольник.
- Белый фон после генерации **вырезать** (soft key по near-white), затем сохранить ARGB.
- На карточке сквозь альфу виден `surface` / цветной wash при выборе — белая подложка ломает вид.

## Стиль

- Фотореализм, коммерческий food/stock, как текущие ассеты.
- Без текста, логотипов, бутылок VIWA (на карточке автомата — только фрукт/зелень).
- Согласование — **на мокапе карточки** (фото слева + название справа), не на белом квадрате.

## Процесс согласования

1. Сгенерировать пачку вариантов (5–10 на вкус).
2. Вырезать фон → 160×156 → пронумерованные мокапы карточек (`P01…`, `M01…`, `A01…`).
3. Пользователь выбирает номера.
4. Только выбранные файлы копировать в `horizontalCard/{key}.png` и обновлять allowlist, если ключ новый.

Рабочие черновики можно складывать вне APK (например `assets/taste-variants-*` в Cursor projects) — в git андроида идут только финальные PNG.

## Связанный код и кросс-репо

При **новом** `tasteMediaKey` (не только замена картинки):

| Репо | Что обновить |
|------|----------------|
| `viwa-android` | PNG, `TasteMediaKeyCatalog`, `ViwaElectronAssets` (PNG; видео опционально) |
| `viwa-telemetry` | `taste-media-keys.ts` + тесты/контракт |
| `viwa-client-web-app` | bottle 800×1000 + medallion 180×180 + манисты (кабинет/лояльность) |

Если для вкуса нет MP4 готовки: `preparingVideoUri` использует **fallback** на существующее видео из пула (не блокировать релиз отсутствием ролика).

Боевые ячейки автомата назначать **только после** OTA с новым APK; на `VIWA-TEST01` можно раньше для smoke.
